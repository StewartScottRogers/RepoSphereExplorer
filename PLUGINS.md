# Plugin registry

Tracks every file-type plugin this project has built or rejected, per
[GUIDANCE.md §3.1](GUIDANCE.md#31-plugin-architecture) and
[§7 D5](GUIDANCE.md#7-open-decisions). Consulted before proposing or
building any plugin work order, so the factory never duplicates a plugin
that already exists or retries a format already ruled out.

| Spreadsheet | `crates/plugins/spreadsheet` | #61 | Covers `.xlsx` and `.ods` as one plugin, per the issue's direction that this document family is one tabular-grid view rather than a plugin per container format. Both are ZIP containers sharing the `archive`/`word-document` plugins' own `PK\x03\x04` magic, so this plugin also requires the raw prefix to contain either `xl/workbook.xml` (the XLSX-specific internal part path, distinct from `word/document.xml`/`ppt/presentation.xml`) or `application/vnd.oasis.opendocument.spreadsheet` (the ODF mimetype, spec-mandated to be the archive's first, uncompressed entry) — markers not used by any sibling plugin; placed just ahead of `archive` in `CORE_PLUGINS`, right after `word-document` (no ordering dependency between the two, kept adjacent since both are ZIP-container document families), so a real spreadsheet is claimed first. Unlike `word-document`'s hand-rolled paragraph walk, correctly reconstructing a sheet's row/column grid needs OOXML's shared-string table and cell-reference indexing (XLSX) and ODF's row/column repeat-count compression (ODS), which is significantly more structural work than flattening paragraph text; this plugin instead reads both formats with the `calamine` crate (already MIT-licensed, matching this project's licence), keeping the plugin's own code to dispatch plus rendering. Reads up to 200 rows per sheet, converting every cell to display text with a small `calamine::Data` match; presents each sheet as its own aligned grid (same shape as `csv`/`parquet`/`avro`/`sqlite`, implemented independently) with a row count and truncation note, but — unlike those tabular plugins — with no header row, since a spreadsheet's first row is arbitrary user data rather than a schema |
| EPUB | `crates/plugins/epub` | #63 | Sniffs by the ZIP `PK\x03\x04` magic plus the `application/epub+zip` mimetype string, which the OCF spec mandates be stored as the archive's first entry, uncompressed — a marker not used by any sibling plugin, following the same fixed-early-offset reasoning as `word-document`'s ODF mimetype check. Reads `META-INF/container.xml` to find the OPF package document's path, then the OPF's `<manifest>` (mapping each item's `id` to its `href`) and `<spine>` (the reading-order list of `idref`s), with a small hand-rolled attribute-value parser (no XML crate, matching this project's other structurally-sniffed formats); reads each spine chapter's XHTML in order and extracts paragraph text with the same hand-rolled tag-stripping walk as `word-document`, generalised to split on any block-level element's closing tag (`p`, `h1`-`h6`, `li`, `blockquote`) rather than a single paragraph tag, since a chapter's heading is itself a paragraph line in this plugin's flat output.
